# Shipwright Improvement Audit

## Current evidence

The public repository is healthy but still early: `main` and tag `v0.1.0` have successful CI runs on Python 3.11 and 3.12, while the repository has no stars or forks yet. The local tree is clean except for the untracked delivery report generated by the previous cycle.

## Gaps with the highest leverage

| Gap | Why it matters | Decision |
|---|---|---|
| No container path | A CLI should be runnable without Python setup in CI or review environments. | Add a minimal non-root Docker image and smoke-test it. |
| No dedicated security workflow | The existing CI checks quality but not dependency or workflow security. | Add separate security workflow with pip-audit and zizmor. |
| SARIF is minimal | GitHub requires SARIF 2.1.0 and uses rule descriptions and locations to render useful alerts [3]. | Add rule metadata, stable artifact locations, and upload-ready workflow. |
| No GitHub contribution templates | A public repository needs predictable issue and PR intake. | Add PR template and issue templates for bug/feature. |
| Broad detector scope can become a reimplementation | OpenSSF Scorecard already evaluates 18 supply-chain checks with remediation [1]; zizmor specializes in GitHub Actions security [2]. | Keep Shipwright as an evidence aggregator and invoke dedicated tools in optional CI, not duplicate their analyzers. |

## Research implications

OpenSSF Scorecard covers source, build, dependencies, testing, and maintenance with weighted security scores [1]. Zizmor performs focused static analysis of GitHub Actions vulnerabilities such as template injection, credential leakage, excessive permissions, and impostor references [2]. GitHub accepts third-party SARIF 2.1.0 results as code-scanning alerts [3]. Therefore the strongest next step is not adding another large security engine; it is making Shipwright operationally composable with those tools while preserving its local deterministic core.

## Improvement slice

The next implementation slice will add a production-friendly container path, security CI, SARIF metadata improvements, contribution templates, and regression tests. These changes increase adoption and maintainer trust without changing the public JSON meanings or introducing a database, network dependency, or unsafe execution path into `shipwright inspect`.
